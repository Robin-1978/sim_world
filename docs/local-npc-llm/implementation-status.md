# Village Slice Implementation Status

The first vertical slice now has a deterministic, headless runtime and a raylib presentation path.

## Runtime

- `WorldService` is the only mutating authority. `WorldState` stores game time, village resources, NPC state, promises, revisions, events, and idempotency keys.
- Mira, Lorn, and Eve have authored schedules, public/hidden goals, boundaries, pressure, memories, relationships, and stage changes.
- `GoalSelector` ranks authored goals. `ActionValidator` rejects provider actions outside the current candidate set. Behavior-tree nodes execute short plans without changing world state directly.
- Mock dialogue is deterministic. `LlamaCppProvider` calls `http://127.0.0.1:8192/v1/chat/completions` and falls back when the service or structured JSON is unavailable.
- Promise transitions cover proposed, accepted, renegotiated, refused, fulfilled, and broken states. Player and NPC parties are both supported.
- Snapshot and JSONL replay restore state without accessing an LLM. The fixed schedule advances all three NPCs while the player is away.

## Client and assets

`assets/blender/village.glb` is generated by `scripts/create_village_scene.py`. The default client is a display-free scene inspector, so CI remains portable. Configure with `-DTIDE_MARKS_FETCH_RAYLIB=ON` to fetch raylib through CMake and build the interactive 3D camera, GLB loading, WASD movement, NPC dialogue, 2D HUD, and ferry collision preview. Bullet 3.25 has a separate `-DTIDE_MARKS_FETCH_BULLET=ON` path; `BulletPhysicsWorld` implements the same `IPhysicsWorld` interface and its collision test passes in the engine build.

## Reproducible validation

```bash
cmake --preset default
cmake --build --preset default
ctest --test-dir build --output-on-failure
./build/tide_marks_headless --scenario village --days 2 --replay /tmp/tide_marks-village.jsonl
# Optional interactive build; dependencies are fetched by CMake
cmake -S . -B build -G Ninja -DTIDE_MARKS_FETCH_RAYLIB=ON -DTIDE_MARKS_FETCH_BULLET=ON
cmake --build build -j2
```

The checked-in nlohmann/json source is consumed through CMake `FetchContent`; raylib and Bullet are pinned URL dependencies when enabled. No API key, model response, build output, or replay artifact belongs in Git.
