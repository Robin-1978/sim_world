# 《潮痕》持续推进目标

这份文件是项目的单页目标摘要。架构契约以 [`design.md`](design.md) 为准；实现状态、验证命令和未建模扩展以 [`release-continuation-plan.md`](release-continuation-plan.md) 为准。

## 第一目标

用真实 LLM 驱动一个持续运行的小世界：三个 NPC 在玩家不持续推动时，仍能依据内驱、外驱、结构约束、可见事实、记忆、知识、经验和私有特质形成不同决策。LLM 理解情境、总结经验、权衡后果并提出一个内容允许的行为计划或行为树；C++ Runtime 校验并执行，事实变化进入下一轮世界演化。

默认产品路径必须使用配置的本地 LLM（当前为 llama.cpp/Qwen）。Mock Provider 只用于单元测试、离线回归、沙箱和没有模型服务时的开发诊断，不能伪装成产品决策器。

## 已冻结的边界

1. `WorldState` 是事实唯一来源。Runtime/C++ 独占权限、规则、事务、Revision、事件和持久化提交。
2. LLM 只能读取经过主体可见性和内容预算裁剪的 `DecisionContext`，返回结构化理解、权衡、意图、参数或演化提案。`runtime_metadata` 只用于关联、过期校验和审计，不进入 NPC 的语义世界快照。
3. `Goal`、`ProcessExecution`、`FSM`、`BT` 是同一个 `NpcActivity` 的不同视角。LLM 选择下一项活动或计划；活动接受后，BT 在多个 Tick 中推进，Tick 不重复调用 LLM。
4. 元动作、BT 节点和行为参数由注册表与内容配置声明。代码只提供通用执行器，不能为具体 NPC、地点、剧情动作或 trigger 增加特例。
5. Content Pack、Game Instance 和运行存档分开。`data/` 保存可复用的静态模板、Schema 和 Intelligence Profile；创建新游戏时模板文档导入该实例唯一的 SQLite，之后内容快照、世界事实、事件、Replay、提案和 Overlay 都由实例数据库保存，原始 JSON 不再是该实例的运行依赖。
6. Level 1 是个体经验与策略演化，Level 2 是世界底座与内容能力演化。两者都由真实 LLM 提案，经过证据校验、沙箱、独立审批、版本化 Overlay 和审计；Runtime Core 不在线热改。
7. Snapshot 是普通读档；Replay 是显式的提交效果验证工件，不在每个 Tick 写盘，也不冒充完整 Event Sourcing。SQLite 由 CMake 固定下载并静态编译，始终提供同一持久化接口。

## 当前闭环

- 三个独立 Content Pack 已经使用同一 Runtime 运行，运行时不依赖 Mira、Lorn、Eve、村庄名称或故事动作。
- 对话先进行 `utterance_understanding`，再由 `player_dialogue` 生成回答和可选行动提案。问候、询问和闲聊可以只产生对白；请求、命令、谈判和承诺才可能提出世界行动。
- 自驱上下文包含主体可见的世界事实、时间、位置、需求、刺激、关系、记忆、知识、经验、私有特质、候选计划和 BT 摘要。LLM 选择已注册计划并填写声明参数，Runtime 再做 Schema、权限、可见性、拓扑、资源和 Revision 校验。
- 被接受的计划持久化为 `ProcessExecution`，完成、失败、显著打断或配置的重评估边界才重新唤醒 LLM。规则系统负责时间、日程、衰减、移动、资源结算和已接受过程。
- 事实变化经统一事务提交，产生带版本、来源和因果关联的 `WorldEvent`，再驱动需求、刺激、关系、记忆、知识和经验。
- Level 1 提案只获得目标 NPC 的私有认知窗口；Level 2 获得经权限裁剪的跨主体摘要。提案不能把一个 NPC 的私有策略无条件共享给所有主体。
- LLM 不可用时，时间和已批准过程仍可推进；对话和新自驱提案明确失败关闭，不使用关键词、固定目标或 Mock 冒充主体决策。

## 验收判据

1. 资源或环境变化会产生需求缺口/刺激，LLM 能解释处境并选择不同计划；计划执行后资源、关系、记忆或经验改变，下一轮选择能引用这些结果。
2. 相同事实下，拥有不同 `private_traits`、关系和经验的 NPC 能稳定地产生可解释的偏好差异；特质只能影响可行候选排序，不能绕过硬约束。
3. BT 由内容配方自动构造，`goto`、交易对象、协作对象和调查目标都是参数；新增组合只需内容和已注册 Operator，不需要角色分支。
4. 普通 Tick 不触发 LLM；玩家交互、自驱重评估、显著刺激和 Level 1/2 演化边界才进入模型队列。
5. Provider 错误、参数错误、Revision 过期、资源不足和权限拒绝都不提交部分事实，并产生可审计结果。
6. Snapshot 恢复、显式 Replay、JSON/SQLite 持久化和三个内容实例回归通过；模型调用不参与恢复或 Replay。

## 后续扩展

只有在对应事实模型、校准数据和失败标准明确后，才继续增加抵押/价格/利率/税费/政策、复杂合同仲裁、大规模事件调度、多模型并发、分布式部署、快照迁移和完整 Event Sourcing。任何新能力都必须先说明可观察事实、注册 Operator、事件与 Snapshot 契约、主体可见范围和 LLM 的治理边界。
