# 《潮痕》持续推进目标

这份文件是项目的单页目标摘要。架构细节以 [`design.md`](design.md) 为准，实施状态以 [`release-continuation-plan.md`](release-continuation-plan.md) 为准。

## 第一目标

用真实 LLM 驱动一个持续运行的小世界：三个 NPC 在玩家不持续推动时，仍能依据内驱、外驱、结构约束、可见事实、记忆、知识和经验形成决策；LLM 解释处境、权衡后果并提出一个内容允许的行为计划或行为树，C++ Runtime 校验并执行，事实变化进入下一轮世界演化。

默认产品路径必须使用配置的本地 LLM（当前为 llama.cpp/Qwen）。Mock Provider 只用于单元测试、离线回归、沙箱和没有模型服务时的开发诊断；它不能伪装成产品决策器。

## 必须保持的边界

1. `WorldState` 是事实唯一来源。Runtime/C++ 独占权限、规则、事务、Revision、事件和持久化提交。
2. LLM 只能读取经过主体可见性裁剪的 `DecisionContext`，并返回结构化理解、权衡、意图、参数或演化提案。公开角色信息与 `private_character` 分离；私密目标和边界可用于内部推理，但不能自动泄露给玩家。LLM 不能直接写事实、调用任意代码或修改 Runtime Core。请求中的 `runtime_metadata` 只用于世界/实例/内容/提示版本关联、异步过期校验和审计，不进入 NPC 的语义世界快照，也不能被模型当作资源、地点或动机事实。
3. `Goal`、`ProcessExecution`、`FSM`、`BT` 是同一 `NpcActivity` 的不同视角；活动槽拥有唯一生命周期，长过程可以被打断、暂停、恢复或失败，但不会把已经提交的世界事实神奇地抹掉。
4. 元动作和 BT 节点由注册表与内容配置声明。代码实现通用执行器，内容包绑定参数、条件、权限、资源策略和组合关系；不能为 Mira、Lorn、Eve 或某个 trigger 增加 C++ 特例。
5. Content Pack、Game Instance 和运行存档分开。`data/` 保存静态定义、Schema 和 Intelligence Profile；运行快照、事件和检查点写到显式 run 路径。

## 两级 LLM 演化

- **Level 1（个体/策略）**：LLM 根据一个有界经验窗口、显著预测误差、连续失败或日边界进行总结、反思和最小创新，提出策略、日程或可执行行为配方变化。提案必须引用已提交事件，经验证、沙箱、独立批准后，以 Overlay 只对声明的 `available_to` 主体生效。
- **Level 2（世界底座/内容能力）**：LLM 根据跨主体异常、资源/关系指标和世界周期边界，提出实体原型、拓扑/内容或声明式能力。它不能在线改事务、权限、事件格式、存档或 C++ Primitive；新能力必须由已注册 Operator 表达，并经过同一治理链。

普通 Tick 不调用 LLM。规则系统负责时间、衰减、移动、资源结算和已接受过程；玩家交互、显著刺激、自驱重评估和演化边界才唤醒模型。演化边界由内容的 `evolution_policy` 配置；到达边界后，Runtime 在时间事务提交后把只读 Level 1/2 上下文放入独立串行队列，模型结果回到主线程后重新验证并自动运行 Sandbox，只有独立审批才能激活 Overlay。一次模型决策可以启动一个跨多个 Tick 的 `ProcessExecution`，直到完成或被更高优先级活动打断。

自驱唤醒阈值比较的是 `DriveEvaluation.effective_weight`（也就是决策上下文中
`drives[].drive` 的数值），不是原始 deficit，也不是一个隐含的归一化百分比。
内容包必须按自身需求权重和优先级校准 `npc_deliberation.min_drive_pressure`；原型内容的
默认阈值应能在初始需求经过少量游戏时间后触发 LLM 重评估。调度器只负责提交异步请求，
不会等待模型；交互主循环在安全的世界边界调用 `pumpAsyncTurns()`。需要在无主循环的
headless 验证中观察真实提案时，使用显式的有界等待入口；超时仍保持失败关闭，不会用
规则或 Mock 代替 LLM。

## 完成判据

- 普通对话先由 LLM 识别话语行为，再由 LLM 生成回应；问候/询问可以只产生对白，请求/命令才可能提出行动。Runtime 不扫描关键词，也不把自驱目标直接当成对话答案。
- 行动提案只能选择当前 `planCatalog` 中的已注册计划；参数经过 JSON Schema、权限、可见性、拓扑、资源和 Revision 重新校验。失败关闭，不猜测、不提交部分事实；模型可收到一次有界、结构化的参数错误反馈。
- 异步提案的并发语义由 decision channel 声明。玩家会话默认要求捕获的 `world_revision` 仍然匹配；自驱通道可以声明允许其他主体先提交不相关事实，以免同一调度边界的多个 NPC 互相使提案过期。这个声明只放宽全局 Revision 的乐观并发检查，不放宽 `npc_state_version`、游戏截止时间、当前资源、拓扑、权限或行为参数校验；冲突仍然失败关闭并写入审计事件。
- 成功行动形成 `WorldEvent`，驱动资源、需求、关系、刺激、记忆、知识和经验；下一次上下文能解释“为什么改变”。知识/经验引用来源事件，不能变成第二份客观世界。
- Level 1 和 Level 2 都由真实 LLM 提案，Runtime 验证、沙箱、独立批准、版本化 Overlay、观察和按栈回退；提案者不能批准自己。
- Snapshot 用于普通读档；Replay 只在显式生成时保存聚合提交效果并校验重建结果，不在每个 Tick 写盘，也不冒充完整 Event Sourcing。SQLite 是可选的 durable checkpoint 适配器；自动写盘默认关闭，只能通过显式的周期或日边界策略启用。
- 同一 Runtime 至少能加载小村庄、港区和 Glass Orchard 三个不同内容实例，不依赖世界名、角色名或故事动作的硬编码。

## 当前阶段与后续顺序

P0–P3 的最小纵向切片已经完成，真实 Qwen 的对话、自驱、Level 1 和 Level 2 提案也已有验证记录。当前继续顺序是：

1. 完成 `WorldService` 的领域协调拆分，保持 `WorldState` 单一写入边界；资源、社会、元动作和调度协调器已抽出，下一步整理自动演化队列与过程/合同协调，再考虑更大规模调度。
2. 已把 durable commit policy 收敛为默认关闭、可注入的周期/日边界检查点策略；继续补充运行配置入口，但不让每个 Tick 阻塞 I/O。
3. 加强真实 LLM 质量回归：对话理解、自驱权衡、完整 BT 执行、参数错误反馈、Level 1/2 提案和模型关闭时的失败关闭。
4. 只有在事实模型、校准数据和失败标准明确后，才增加商店、价格、利率、税费、政策、复杂仲裁或大规模社会模拟。

任何新功能都必须先回答：它增加了什么可观察事实？由哪个注册 Operator 提交？事件和 Snapshot 如何保存？哪些主体能看到？LLM 如何提出而不能越权？
